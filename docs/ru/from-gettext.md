# Переход с gettext

Два пути: оставить свой процесс с `.po` и загружать то, что собирает
`msgfmt`, или сконвертировать один раз и оставить gettext позади.

- [Загрузка .mo напрямую](#загрузка-mo-напрямую)
- [Конвертация .po](#конвертация-po)
- [Почему нет читателя .po](#почему-нет-читателя-po)

## Загрузка .mo напрямую

Загружайте `.mo`, которые у вас уже собираются, без libintl и без
конвертации:

```c
ci18n_load_mo("ru", "locale/ru/LC_MESSAGES/app.mo");
ci18n_set_current("ru");
ci18n_get("Hello, world");     /* keys are the msgids */
ci18n_plural("%d file", n);    /* msgid_plural works too */
```

| gettext | ключ ci18n |
| --- | --- |
| `msgid "Open"` | `Open` |
| `msgctxt "menu"` вместе с `msgid "Open"` | `menu.Open` |
| `msgid_plural` с `msgstr[0]`, `msgstr[1]`, ... | `msgid[one]`, `msgid[few]`, ... |

Формы плюрала раскладываются по категориям CLDR по `nplurals` из заголовка.
Читаются оба порядка байт, и каждое смещение проверяется до использования,
так что битый файл отвергается, а не читается за границей.
`ci18n_load_mo_from_buffer` берёт файл, уже лежащий в памяти. Загрузчик
занимает около 2,5 КБ кода; определите `CI18N_NO_MO`, чтобы его не было.

## Конвертация .po

Чтобы уйти с gettext совсем, `tools/po2ci18n.py` превращает каталог `.po` в
файл перевода ci18n:

```bash
tools/po2ci18n.py ru.po -o translations/ru.txt
tools/po2ci18n.py --keys=slug ru.po -o translations/ru.txt
```

Он понимает экранирование и переносы длинных записей, которые пишет gettext,
раскладывает `msgid_plural` с его индексными `msgstr[0]`, `msgstr[1]` по
именам категорий CLDR, превращает `msgctxt` в префикс ключа и пропускает
записи fuzzy, непереведённые и устаревшие. `--keys=slug` превращает
английские предложения в короткие идентификаторы, что снимает ограничение
`CI18N_MAX_KEY_LENGTH`.

Оба пути дают одни и те же ключи. `make test-po` прогоняет конвертер по
образцовому каталогу и загружает результат обратно, а `make test-mo` собирает
тот же образец через `msgfmt` в обоих порядках байт и проверяет, что
загрузчик `.mo` получает ровно то, что записал конвертер.

## Почему нет читателя .po

Полный читатель это около 700 строк, из них 300 на вычислитель выражения на
C, которое gettext кладёт в заголовок Plural-Forms. Это удвоило бы
поверхность разбора у библиотеки, смысл которой в одном небольшом заголовке.
Конвертация на этапе сборки вычисляет это выражение на вашей машине, а не на
устройстве, а загрузчику `.mo` нужно только число форм.
