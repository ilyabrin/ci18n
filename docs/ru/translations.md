# Переводы

Что пишется в файл перевода и как один ключ покрывает «1 файл», «3 файла» и
«1st place» в любом языке.

## Формат файла

Одна пара `key=value` на строку. Пустые строки и строки, начинающиеся с `#`
или `;`, пропускаются, пробелы вокруг ключа и значения обрезаются, BOM UTF-8
в начале файла игнорируется. Строку завершает LF, CRLF или одиночный CR.

```ini
# This is a comment
greeting=Hello!
farewell=Goodbye!
error=An error occurred
```

Загрузка в уже существующий язык сливается с ним: новые ключи добавляются,
существующие заменяются, остальное не трогается.

## Экранирование

Иначе значение берётся буквально, так что только так можно вставить в
перевод перевод строки или знак равенства:

| Пишется | Становится |
| --- | --- |
| `\n` | перевод строки |
| `\t` | табуляция |
| `\r` | возврат каретки |
| `\\` | обратная косая черта |
| `\=` | знак равенства, так ключ может его содержать |
| `\#` и `\;` | ключ может начинаться с символа комментария |
| `\ ` | пробел, который обрезка не съест |

```ini
multiline=First line.\nSecond line.
we\=ird=a key with an equals sign in it
padded=keeps one trailing space\
```

Эти последовательности декодируют только загрузчики файлов и буферов.
`ci18n_set()` принимает строки, которые компилятор C уже раскрыл, поэтому
`ci18n_set("en", "path", "C:\\new")` сохраняет путь Windows, а не перевод
строки.

Нераспознанная последовательность сохраняет оба символа: `\q` остаётся `\q`.
Ошибка в переводе должна быть видна, а не молча съедать следующий символ.

## Плюралы

Таблица ключ-значение не может перевести русский: ему нужны три формы там,
где английскому хватает двух. Формы плюрала это обычные ключи с категорией
CLDR в квадратных скобках:

```ini
# en
files[one]=%d file
files[other]=%d files

# ru
files[one]=%d файл
files[few]=%d файла
files[many]=%d файлов
```

Дальше спрашивайте по количеству:

```c
printf(ci18n_plural_or_key("files", n), n);
```

```
en:   1 file    2 files    5 files    11 files    21 files
ru:   1 файл    2 файла    5 файлов   11 файлов   21 файл
```

Обратите внимание на 11 и 21: правило, которое просто сравнивает с 1,
в русском ошибается. Поэтому категория берётся из CLDR, а не из кода
вызывающего. Поиск идёт по `key[category]`, затем по `key[other]`, затем по
простому `key`, так что перевод может быть ровно настолько подробным,
насколько нужно. Все три варианта берутся из одного языка: сначала из
текущего, и только если в нём нет ни одного, из запасного, причём форму тогда
выбирают правила запасного языка.

Правила известны для 71 языка и сгруппированы так же, как в CLDR:
английский и похожие, французский и португальский, русский, украинский и
белорусский, польский, чешский и словацкий, хорватский и сербский, арабский,
иврит с его двойственным числом, литовский, латышский, словенский, ирландский,
румынский и языки без различия по числу, такие как японский, китайский и
корейский. У французского, португальского, испанского, итальянского и
каталанского есть ещё форма «many» для целого числа миллионов,
«1 000 000 de fichiers», и перевод может её пропустить, потому что поиск
откатится к `[other]`. Неизвестный язык считается похожим на английский.
Учитываются только целые количества.

Каждый поддерживаемый язык проверяется юнит-тестами по CLDR 48, на примерах
чисел, которые CLDR публикует рядом с каждым правилом. См.
[tools/cldr_samples.py](../../tools/cldr_samples.py).

`ci18n_plural_category(lang, n)` даёт только категорию, а
`ci18n_plural_category_name(cat)` её название, для инструментов, которым они
нужны. Чтобы заодно подставить количество и другие значения, используйте
`ci18n_format_plural`; см.
[Форматирование](formatting.md#плюралы-со-значениями).

## Порядковые числительные

«Первый, второй, третий» это другой вопрос, чем «один, два, три», со своими
правилами. В английском четыре порядковые формы, и 11, 12 и 13 получают «th»,
хотя кончаются на 1, 2 и 3. У русского, немецкого, испанского и большинства
других форма одна, потому что их порядковое числительное это слово, которое
согласуется с существительным, а не суффикс.

Ключи порядковых форм используют те же скобки, что и плюралы:

```ini
place[one]={count}st place
place[two]={count}nd place
place[few]={count}rd place
place[other]={count}th place
```

```c
ci18n_format_ordinal(out, sizeof(out), "place", 22, NULL);  /* 22nd place */
ci18n_format_ordinal(out, sizeof(out), "place", 12, NULL);  /* 12th place */
```

Немецкий перевод пишет только `place[other]={count}. Platz`, и её получает
любое число. Держите порядковые и количественные формы под разными ключами:
`files[one]` и `place[one]` означают разное.

`ci18n_ordinal(key, n)` возвращает форму без подстановки, а
`ci18n_ordinal_category(lang, n)` только категорию. У неизвестного языка
порядковых форм нет, потому что «other» это та, что есть в любом переводе.

## Все ключи языка

`ci18n_foreach(lang, fn, user_data)` вызывает `fn` для каждой записи, формы
плюрала тоже, под их сохранёнными ключами вроде `files[one]`. Верните `false`
из колбэка, чтобы остановиться раньше. Порядок не определён.

```c
static bool print_entry(const char *key, const char *value, void *user_data)
{
    (void)user_data;
    printf("%s = %s\n", key, value);
    return true;
}

ci18n_foreach("ru", print_entry, NULL);
```

Так инструмент находит ключи, о которых заранее не знал;
[examples/cli_sync](../../examples/cli_sync/) строит на этом проверку
переводов. Колбэк не должен обращаться обратно к библиотеке.
