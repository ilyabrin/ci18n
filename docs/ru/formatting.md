# Форматирование

Как подставлять значения в переводы: имена, количества, даты, которые вы
выводите сами, и числа в том виде, в каком их пишет каждый язык.

Всё на этой странице выключается `CI18N_NO_FORMAT`, а числа
`CI18N_NO_NUMBERS`; см. [Встраиваемые системы и размер](embedded-and-size.md).

## Плейсхолдеры

Значения попадают в перевод по имени, а не по позиции, потому что их порядок
определяет перевод:

```ini
# en
greeting=Hello, {name}! You have {count} messages.

# ru
greeting=Привет, {name}! У вас {count} сообщений.
```

```c
char text[256];
ci18n_format(text, sizeof(text), "greeting", "name", user, "count", "3", NULL);
```

После ключа идут пары «имя, значение», в конце `NULL`.

Два сознательных решения, о которых стоит знать:

- **Значения это строки, а не строка формата.** Файл перевода это данные,
  часто написанные не программистом. Передать его в `printf()` как формат
  значит сделать каждого переводчика потенциальным атакующим.
- **Несовпавший плейсхолдер остаётся как есть.** `{nmae}` выводится как
  `{nmae}`, так что опечатка видна, а не превращается в тихую дыру.

Пишите `{{` и `}}` для буквальных фигурных скобок.

## Плюралы со значениями

Вместе с [плюралами](translations.md#плюралы), где это и окупается:

```ini
inbox[one]={name}, у вас {count} новое сообщение
inbox[few]={name}, у вас {count} новых сообщения
inbox[many]={name}, у вас {count} новых сообщений
```

```c
ci18n_format_plural(text, sizeof(text), "inbox", n, "name", user, NULL);
```

```
Илья, у вас 1 новое сообщение
Илья, у вас 3 новых сообщения
Илья, у вас 5 новых сообщений
```

`{count}` заполняется из самого количества, поэтому пара для него не нужна.
Передайте её всё равно, чтобы подменить значение: так выводят «99+» и при
этом выбирают правильную форму. `ci18n_format_ordinal` делает то же для
[порядковых числительных](translations.md#порядковые-числительные).

## Буферы и обрезка

Функции форматирования ведут себя как `snprintf()`: пишут не больше
`capacity - 1` байт, всегда завершают строку и возвращают длину, которую
имел бы весь результат, так что возврат `capacity` или больше означает
обрезку. `ci18n_format(NULL, 0, ...)` только измеряет, ничего не записывая.

Обрезанный результат всегда корректный UTF-8 и всегда начало полного:
разрез никогда не попадает внутрь символа.

```c
char out[8];

ci18n_set("ru", "greeting", "Привет");
ci18n_format(out, sizeof(out), "greeting", NULL);  /* returns 12 */
/* out is "При", 6 bytes, not 7 bytes ending in half a character */
```

## Форматтеры

Дата в предложении это задача перевода дважды. Где она стоит, решает
переводчик, и это уже решают именованные плейсхолдеры. Как она выглядит,
решает локаль, а её эта библиотека не узнает никогда, потому что знать это
значит поставлять CLDR.

Поэтому перевод называет форматтер, а ваш код его предоставляет:

```ini
invoice=Issued {created:date,long}, due {due:date,short}
```

```c
static size_t format_date(char *out, size_t capacity, const char *value,
                          const char *arg, void *user_data)
{
    (void)user_data;
    return my_render_date(out, capacity, value, arg);  /* your date code */
}

ci18n_set_formatter("date", format_date, NULL);

ci18n_format(text, sizeof(text), "invoice",
             "created", "2026-09-23",
             "due", "2026-10-07", NULL);
```

Разбор, поиск и арифметику буферов делает библиотека. Вывод делаете вы, тем,
чем уже выводите даты. Переводчик может переставить плейсхолдер, попросить
другую форму или убрать его, не трогая ваш код.

Синтаксис такой: `{name:formatter}` или `{name:formatter,argument}`. Всё
после первой запятой это аргумент, дословно, так что форматтер может задать
там свой синтаксис:

```ini
price=Total: {amount:currency,USD}
when=Updated {ts:relative}
pad=[{label:pad,12,right}]
```

Ваша функция ведёт себя как `snprintf`: пишет не больше `capacity - 1` байт,
завершает строку, если ёмкость не нулевая, и возвращает длину, которую имел
бы весь результат. Библиотека вызывает её с `out = NULL` и `capacity = 0`,
чтобы измерить, так что обработайте этот случай без записи. `value` и `arg`
никогда не NULL; `arg` равен `""`, если перевод его не дал. `user_data`
возвращается нетронутым, так что в нём можно передать объект локали.

Плейсхолдер с форматтером, который никто не зарегистрировал, остаётся
видимым, а `ci18n_last_error()` сообщает `CI18N_ERR_UNKNOWN_FORMATTER`.
Остальное предложение всё равно выводится, потому что отсутствующий
форматтер это повод увидеть дефект, а не потерять текст вокруг него.

```c
ci18n_format(out, sizeof(out), "invoice", "created", "2026-09-23", NULL);
/* out is "Issued {created:date,long}, due ..." and the error says why */
```

Форматтеры принадлежат каталогу и не наследуются от каталога по умолчанию.
Библиотека со своим каталогом регистрирует свои, в этом и смысл каталогов, и
заодно форматированию никогда не нужно держать две блокировки сразу.
Используйте для этого `ci18n_set_formatter_in` и `ci18n_format_in`.

В shared-режиме форматтер выполняется, пока удерживается блокировка чтения
каталога. Поэтому он не должен обращаться обратно к библиотеке и должен
безопасно работать в нескольких потоках одновременно.

## Числа

Одно и то же число в четырёх языках пишется четырьмя способами:

| Язык | `1234567.5` | `{n:number,2}` от `19.999` |
| --- | --- | --- |
| en | 1,234,567.5 | 20.00 |
| de | 1.234.567,5 | 20,00 |
| ru | 1 234 567,5 | 20,00 |
| hi | 12,34,567.5 | 20.00 |

`number` это встроенный форматтер, так что переводу достаточно его назвать:

```ini
total=Total: {n:number}
price=Price: {n:number,2} USD
files[other]={count:number} files
```

```c
ci18n_format(out, sizeof(out), "total", "n", "1234567.5", NULL);
ci18n_format_number(out, sizeof(out), "de", "1234567.5", -1);  /* directly */
```

- **Значение это строка**, например `"-1234.5"`, так что double не округлит
  его по дороге. Своё число сначала выведите через `%ld` или `%.2f`.
- **Аргумент это число знаков после запятой.** Без него остаётся столько,
  сколько есть в значении; `2` округляет или дополняет до двух, половину к
  чётному, как в CLDR.
- **Для каждого языка из CLDR**: десятичный разделитель и разделитель групп,
  знак минуса, группируется ли 1234 вообще (испанский и польский ждут до
  12 345), и индийское 12,34,567. Покрыт 71 язык с правилами плюрала, меньше
  чем в 1 КБ. [tools/cldr_numbers.py](../../tools/cldr_numbers.py) генерирует
  таблицу и сверяет каждый язык с CLDR.
- **Решает текущий язык.** Неизвестный пишется по-английски, как и плюралы
  у него английские.
- **Всё остальное проходит как есть.** `1e9` или `12,5` выходят такими же,
  а форматтер, зарегистрированный под именем `number`, заменяет встроенный.

Цифры везде от 0 до 9: у арабского, персидского, бенгальского и ещё
нескольких есть свои национальные цифры, но CLDR для каждого языка
перечисляет и латинские, их библиотека и пишет.
