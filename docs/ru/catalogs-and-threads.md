# Каталоги и потоки

Как использовать ci18n внутри библиотеки и не спорить с приложением о текущем
языке, и как использовать её из нескольких потоков.

- [Каталоги](#каталоги)
- [Потоки](#потоки)
- [Shared-режим](#shared-режим)

## Каталоги

Всё в [начале работы](getting-started.md) работает с одним каталогом,
которым владеет библиотека. Для программы удобно, для библиотеки неправильно:
если ci18n используется внутри переиспользуемого компонента, у компонента и
у приложения, которое его подключило, один текущий язык на двоих, и
побеждает тот, кто последним вызвал `ci18n_set_current()`.

Поэтому у каждой функции есть вариант `_in`, принимающий каталог явно, а
простые имена это те же варианты, применённые к каталогу по умолчанию:

```c
ci18n_t *ui   = ci18n_create();
ci18n_t *logs = ci18n_create();

ci18n_load_language_in(ui, "ru", "ru.txt");
ci18n_set_current_in(ui, "ru");

ci18n_load_language_in(logs, "en", "en.txt");
ci18n_set_current_in(logs, "en");

puts(ci18n_get_or_key_in(ui, "greeting"));     /* Russian */
puts(ci18n_get_or_key_in(logs, "greeting"));   /* English */

ci18n_destroy(ui);
ci18n_destroy(logs);
```

У каталога свои языки, свой текущий и запасной язык, свои
[форматтеры](formatting.md#форматтеры), а в shared-режиме и своя блокировка,
так что два каталога никогда не ждут друг друга. `ci18n_default()`
возвращает тот, с которым работают простые функции, так что код на функциях
`_in` тоже может до него добраться.

`ci18n_destroy(NULL)` ничего не делает, так что неудачное создание не
требует особого случая.

## Потоки

Три режима. Выберите один до подключения заголовка; два сразу это ошибка.

| Режим | Что получаете |
| --- | --- |
| ничего не определено | Один глобальный контекст, без блокировок |
| `CI18N_THREAD_LOCAL_CONTEXT` | Отдельный контекст на каждый поток |
| `CI18N_THREAD_SHARED` | Один общий контекст за блокировкой чтения-записи |

**По умолчанию.** Безопасно, если все загрузки закончились до запуска
потоков, а дальше они только читают, и так устроено большинство программ.
Одновременный `ci18n_set()` или `ci18n_load_*()` с одновременным
`ci18n_get()` это гонка данных.

**`CI18N_THREAD_LOCAL_CONTEXT`.** Изоляция, а не общий доступ. Каждый поток
вызывает `ci18n_init()` и загружает свои переводы, и язык, загруженный в
одном потоке, не виден другим. Подходит для обработчика, который выводит
текст на языке одного пользователя. `CI18N_THREAD_SAFE` это старое имя этого
режима; оно работает и выдаёт предупреждение об устаревании.

**`CI18N_THREAD_SHARED`.** Один контекст и блокировка чтения-записи вокруг
каждой точки входа. Читатели не блокируют друг друга, писатель исключает
всех. Это случай «загрузили один раз, читаем из многих потоков, изредка
перезагружаем».

## Shared-режим

```c
#define CI18N_THREAD_SHARED
#define CI18N_IMPLEMENTATION
#include "ci18n.h"
```

О нём стоит знать три вещи.

**Используйте `ci18n_get_copy()`, а не `ci18n_get()`.** Блокировка не может
сделать возвращённый указатель безопасным: как только она отпущена, писатель
может перевыделить память, на которую он указывает. `ci18n_get_copy()`
копирует, пока блокировка чтения ещё удерживается, и так же поступают
`ci18n_format` и родственные функции.

```c
char text[128];
ci18n_get_copy("greeting", text, sizeof(text));
```

**Диагностика своя у каждого потока.** `ci18n_last_error()` и
`ci18n_last_load_stats()` описывают последний вызов вызывающего потока, а не
контекста. Общий слот означал бы, что потоки перезаписывают друг друга.

**Перезагружайте загрузкой поверх.** Загрузка сливается с языком под одной
блокировкой записи, так что читатель видит старый текст или новый. Сначала
очистить, потом загрузить это две блокировки, и читатель может попасть
между ними и не найти ключ.

На glibc этот режим требует `-D_POSIX_C_SOURCE=200809L` или `-std=gnu99`
вместо `-std=c99`, потому что строгий режим ANSI прячет объявления POSIX для
потоков. Если забудете, заголовок скажет об этом через `#error`.

**Чтение масштабируется по ядрам.** Каталог держит 16 блокировок, каждую на
своей строке кэша, и каждый поток читает через свою, так что читатели никогда
не трогают одну и ту же память. По `make bench-threads` один поток делает
26 миллионов вызовов `ci18n_get` в секунду, а восемь потоков вместе 146
миллиона, столько же, сколько восемь отдельных каталогов. Цена на стороне
записи: писатель берёт все 16 блокировок, так что `ci18n_set()` и загрузчики
в этом режиме стоят чуть дороже, что подходит для «загрузили один раз,
перезагружаем редко».

Серверу обычно нужен каталог на каждый язык, потому что у каталога один
текущий язык, а сервер обслуживает все сразу.
[examples/server](../../examples/server/) показывает эту схему с
перезагрузкой под четырьмя читателями.
