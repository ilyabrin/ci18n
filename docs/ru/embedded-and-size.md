## Сколько весит

Код и константные данные реализации, замерено gcc:

| Сборка | x86-64 `-O2` | x86-64 `-Os` | Cortex-M4 `-Os` |
| --- | --- | --- | --- |
| Всё включено | 40 КБ | 28 КБ | 13,6 КБ |
| `CI18N_MINIMAL` | 22 КБ | 15 КБ | 7,6 КБ |

Сам заголовок это 208 КБ исходника, в основном комментарии, и компилируется
он только в одном файле.

## Что можно выключить

По умолчанию включено всё. Каждый из этих макросов убирает возможность
целиком, код и данные, и перестаёт объявлять её функции, так что вызов
такой функции становится ошибкой компиляции, а не сюрпризом во время работы:

| Макрос | Что убирает | Экономия при `-Os`, x86-64 / Cortex-M4 |
| --- | --- | --- |
| `CI18N_NO_FORMAT` | `ci18n_format` и родственные, форматтеры, изоляцию bidi | 4,9 / 1,8 КБ и от 260 до 330 байт на каталог |
| `CI18N_NO_MO` | загрузчик `.mo` из gettext | 2,7 / 1,3 КБ |
| `CI18N_NO_ORDINALS` | `ci18n_ordinal` и родственные | 2,6 / 1,0 КБ |
| `CI18N_NO_NUMBERS` | `ci18n_format_number` и `{n:number}` | 2,2 / 1,4 КБ |
| `CI18N_NO_FILES` | все загрузчики, открывающие файл | 1,2 / 0,4 КБ |
| `CI18N_NO_LOCALE` | `ci18n_detect_locale`, `ci18n_set_current_best` | 0,7 / 0,4 КБ |
| `CI18N_NO_COMPILED` | `ci18n_use_compiled`, [скомпилированные каталоги](compiled-catalogs.md) | 0,8 / 0,4 КБ |
| `CI18N_MINIMAL` | всё перечисленное, кроме `CI18N_NO_COMPILED` | 13 / 6,0 КБ, примерно половина |

```c
#define CI18N_MINIMAL
#define CI18N_IMPLEMENTATION
#include "ci18n.h"
```

Что остаётся в любой сборке: загрузка из буферов, поиск, плюралы, запасной
язык, каталоги, направление текста, UTF-8 хелперы и диагностика.
`CI18N_MINIMAL` сохраняет скомпилированные каталоги, которые маленькой
сборке нужнее всего; добавьте `CI18N_NO_COMPILED`, чтобы убрать и их. CI
собирает и тестирует каждый макрос отдельно и все вместе.

## Когда это уже делает линкер

Экономия выше посчитана для всей реализации. Именно её оставляют gcc и clang
по умолчанию и любая разделяемая библиотека, потому что каждая публичная
функция сохраняется. С
`-ffunction-sections -fdata-sections -Wl,--gc-sections`, а это умолчание в
ESP-IDF, Zephyr, STM32Cube и ядрах Arduino, линкер сам выбрасывает то, что
вы не вызываете. Там [tests/minimal.c](../../tests/minimal.c), поиск и
плюрал, занимает 7,1 КБ кода библиотеки на Cortex-M4 со всем включённым и
6,2 КБ с `CI18N_MINIMAL`, а макросы экономят то, что линкер разглядеть не
может: правила порядковых форм, связанные с поиском плюрала, и 260 байт RAM
на каталог под таблицу форматтеров.

## Лимиты

Определите их до подключения заголовка. Каждый каталог это структура
фиксированного размера, так что они определяют её цену в RAM:

```c
#define CI18N_MAX_KEY_LENGTH 256
#define CI18N_MAX_VALUE_LENGTH 4096
#define CI18N_MAX_LANGUAGES 32
#define CI18N_MAX_KEYS_PER_LANGUAGE 1024
#define CI18N_MAX_CODE_LENGTH 32
#include "ci18n.h"
```

Показаны значения по умолчанию. `CI18N_MAX_LINE_LENGTH`,
`CI18N_MAX_FORMATTERS`, `CI18N_MAX_FORMATTER_NAME` и
`CI18N_MAX_FORMATTER_ARG` задаются так же. Загрузка, упёршаяся в лимит,
сообщает об этом в своей статистике; см.
[Начало работы](getting-started.md#когда-что-то-пошло-не-так).

## Память

| Что | Размер |
| --- | --- |
| Пустой каталог | 3,5 КБ, без кучи; 0,4 КБ с `CI18N_MINIMAL` и 4 языками на 32-битной цели |
| Каталог по умолчанию | 3,5 КБ статической памяти |
| `CI18N_THREAD_LOCAL_CONTEXT` | 3,5 КБ на каждый поток, вызвавший `ci18n_init()` |
| Загруженные переводы | примерно в 1,4 раза больше файла |

Язык на 1 000 ключей из файла в 66 КБ занимает 94 КБ кучи, на 10 000 ключей
из 664 КБ занимает 0,9 МБ. Загрузка возвращает запас, до которого выросли её
буферы: это одно копирование, и загрузка становится примерно на 20%
медленнее. Пока вы ничего не сохранили, ничего не выделяется.

## Компоновка

`CI18N_DEF` стоит перед каждой публичной функцией. Переопределите его, чтобы
изменить компоновку библиотеки:

```c
#define CI18N_DEF static                  /* keep the API private to one file */
#define CI18N_DEF __declspec(dllexport)   /* export from a Windows DLL */
#define CI18N_DEF __declspec(dllimport)   /* consume that DLL */
```

Со `static` ждите `-Wunused-function` для каждой функции API, которую вы не
вызываете.

## Маленькие устройства

Самая маленькая цель это Arduino Uno: 8 бит, 2 КБ RAM, 32 КБ флеша. CI
гоняет юнит-тесты на ATmega2560 и на ATmega328P из Uno под QEMU, на голом
железе на Cortex-M3 с newlib и на RV32, классе ESP32-C3, с picolibc; см.
[Платформы](platforms.md).

Что обычно нужно сборке для устройства:

- **Переводы встроены в прошивку.** [Скомпилированные каталоги](compiled-catalogs.md)
  не тратят RAM совсем: три языка на Cortex-M4 ушли с 3,2 КБ кучи до нуля.
  Определите `CI18N_NO_FILES`, если файловой системы нет.
- **Лимиты по размеру продукта.** Четыре языка и несколько десятков ключей
  дают каталог в несколько сотен байт.
- **Текст извне проверяется первым.** `ci18n_utf8_valid` до загрузки пакета
  языка, пришедшего по воздуху.

[examples/embedded_ui](../../examples/embedded_ui/) это дисплей 20x4 на трёх
языках, один из них справа налево, собранный именно так.

### Arduino и AVR

Это библиотека для Arduino и для PlatformIO. В Arduino IDE выберите
Sketch > Include Library > Add .ZIP Library и укажите архив релиза с GitHub.
В PlatformIO, из [реестра](https://registry.platformio.org/libraries/ilyabrin/ci18n):

```ini
lib_deps = ilyabrin/ci18n@^2.18.0
```

Дальше подключите в скетче `ci18n.h`, и больше ничего. Реализацию библиотека
компилирует сама, поэтому `CI18N_IMPLEMENTATION` в скетче не определяйте.
[examples/arduino/Hello](../../examples/arduino/Hello/Hello.ino) выводит два
языка с плюралами в монитор порта.

На AVR отличаются три вещи, и все три включаются сами:

- **Малые лимиты.** Включён `CI18N_SMALL_LIMITS`: ключи до 64 байт, значения
  до 256, 4 языка по 64 ключа, и каталог занимает 0,3 КБ. Любой лимит,
  заданный вами, по-прежнему главнее, а сам макрос годится и для любой
  другой маленькой цели.
- **Таблицы во флеше.** avr-gcc при старте копирует в RAM каждую константу,
  если не сказать ему иначе. Собственные таблицы библиотеки, правила
  плюралов и символы чисел, и каждый скомпилированный каталог лежат во
  флеше.
- **Переводы копируются наружу.** Строку во флеше нельзя прочитать через
  обычный указатель, поэтому функции, которые его возвращают, `ci18n_get()`,
  `ci18n_plural()`, `ci18n_ordinal()` и родственные, дают ошибку компиляции
  с названием замены. Читайте переводы функциями, которые заполняют буфер:

```c
char line[48];

ci18n_get_copy("title", line, sizeof(line));
ci18n_plural_copy("files", count, line, sizeof(line));
ci18n_format_plural(line, sizeof(line), "files", count, NULL);
```

Они работают на любой платформе, так что такой код переносится куда угодно.
Если определить `CI18N_NO_COMPILED`, функции с указателями вернутся, а
останутся только языки, загруженные во время работы, и они живут в RAM.

Каталоги компилируются на вашем компьютере, как для любой цели; см.
[Скомпилированные каталоги](compiled-catalogs.md). Значение копируется в
буфер из `CI18N_MAX_VALUE_LENGTH` байт, поэтому каталог с более длинным
значением на AVR даёт ошибку сборки, а не обрезанный перевод. Этот же буфер
составляет большую часть RAM, которую берёт библиотека: уменьшите лимит,
чтобы сократить его.

Во что это обходится на Uno:

| Сборка | Флеш | RAM |
| --- | --- | --- |
| Пример Hello: 2 языка, плюралы, форматирование | 9,5 КБ | 0,7 КБ |
| `CI18N_MINIMAL`, 2 скомпилированных языка, поиск и плюрал | 6,4 КБ | 0,6 КБ |

Цифры показывают, сколько библиотека и её каталоги добавляют к пустому
скетчу. Константные данные должны лежать в первых 64 КБ флеша, и avr-gcc
сам так их и размещает на любой плате, кроме очень заполненной Mega.
