# Скомпилированные каталоги

Переводы, встроенные в программу как константные данные: ничего не
разбирается при старте, нет кучи, а ключи проверяет компилятор.

## Что это меняет

Замерено на каталоге из 1 000 ключей, который использует `make bench`, на
Linux x86-64, gcc `-O2`, и на [examples/embedded_ui](../../examples/embedded_ui/)
для Cortex-M4:

| | Загрузка во время работы | Скомпилированный |
| --- | --- | --- |
| Куча на 1 000 ключей (файл 68 КБ) | 98 КБ | нет |
| Старт, 1 000 ключей | 0,19 мс | меньше 0,1 мкс |
| Старт, 10 000 ключей | 2,2 мс | меньше 0,1 мкс |
| `ci18n_get`, ключ найден | 29 нс | 29 нс |
| `ci18n_get`, ключа нет | 19 нс | 15 нс |
| RAM на три языка на Cortex-M4 | 3,2 КБ кучи | нет |
| Флеш под них | текст | текст и 0,6 КБ хеш-таблиц |

Поиск стоит столько же: большая часть работы это хеширование ключа, в любом
случае. Уходят разбор, куча и ещё одно: строка из скомпилированного языка
живёт столько же, сколько программа, так что правила
[времени жизни указателей](getting-started.md#время-жизни-указателей) к ней
не относятся, с потоками или без.

Код библиотеки для этого занимает 0,8 КБ при `-Os` на x86-64 и 0,4 КБ на
Cortex-M4. `CI18N_NO_COMPILED` его убирает.

## Как использовать

Соберите генератор один раз, затем скомпилируйте файл перевода в заголовок:

```bash
cc -Iinclude -o ci18n_compile tools/ci18n_compile.c
./ci18n_compile -o ru.h ru translations/ru.txt
```

```c
#define CI18N_IMPLEMENTATION
#include "ci18n.h"
#include "ru.h"                                   /* ci18n_compiled_ru */

ci18n_init();
ci18n_use_compiled("ru", &ci18n_compiled_ru);    /* records a pointer */
ci18n_set_current("ru");
puts(ci18n_get("greeting"));                      /* as with any language */
```

Всё, что читает, работает так же: `ci18n_get`, плюралы, порядковые формы,
`ci18n_format`, `ci18n_foreach`, запасной язык, каталоги и все три режима
потоков. Формат файла тот же, что в [Переводах](translations.md).

Генератор читает файл собственным загрузчиком библиотеки, так что файл
значит одно и то же скомпилированным и загруженным; тесты проверяют это на
каждом пуше, на каждой платформе. То, что загрузчик молча выбросил бы,
становится ошибкой сборки:

```
translations/ru.txt:22: no '=' on the line (1 such lines)
```

Так же падает ключ или значение длиннее лимитов `CI18N_MAX_*`. Если ваша
программа поднимает эти лимиты, соберите генератор с теми же настройками.

Сгенерированные данные не зависят от порядка байт: генерируйте на своём ПК и
собирайте под любую цель. Заголовок другой версии формата
`ci18n_use_compiled` отвергает с `CI18N_ERR_PARSE`, так что после обновления
ci18n сгенерируйте заново.

## В сборке

**make** или скрипт: соберите `ci18n_compile` для машины, на которой идёт
сборка, и запустите его для каждого языка до компиляции программы.

**CMake**: одна строка на язык, и заголовок пересоздаётся при каждом
изменении текстового файла.

```cmake
ci18n_compile_translations(app ru translations/ru.txt)
ci18n_compile_translations(app en translations/en.txt)
```

Это работает, когда ci18n добавлена как подпроект, через FetchContent или
установлена и найдена через `find_package(ci18n)`. Генератор собирается из
исходника, когда впервые нужен, вашим же компилятором. При кросс-компиляции,
например под микроконтроллер, собранный под цель генератор не запустится,
поэтому соберите `tools/ci18n_compile.c` для своего ПК и укажите его в
`CI18N_COMPILE_EXECUTABLE`.

## Проверяемые ключи

Сгенерированный заголовок заодно определяет макрос на каждый ключ, и
`CI18N_KEY()` превращает опечатку в ключе в ошибку компиляции:

```c
ci18n_get(CI18N_KEY(greeting));    /* the string "greeting" */
ci18n_get(CI18N_KEY(greting));     /* error: 'ci18n_key_greting' undeclared */
```

Ключ плюрала считается один раз, по основе: `files[one]` и `files[other]`
дают `CI18N_KEY(files)`. `CI18N_KEY` это обычная строка, так что он работает
и с языками, загружаемыми во время работы. Чтобы проверять ключи, не
компилируя переводы, сгенерируйте одни макросы ключей:

```bash
./ci18n_compile --keys-only -o keys.h en translations/en.txt
```

Ключ, который не является идентификатором C, например `menu.open` или msgid
из gettext, макроса не получает; генератор такие перечисляет, а `--strict`
делает их ошибкой. Как обычные строки такие ключи по-прежнему работают.
`CI18N_KEY` не является константным выражением, так что им нельзя
инициализировать статическую переменную.

## Скомпилированные и загружаемые вместе

Один каталог может держать оба вида. Типичная схема на устройстве: языки,
которые идут с прошивкой, скомпилированы, а пакет языка, полученный позже,
загружается из буфера, и скомпилированный язык служит ему запасным.

Скомпилированный язык только для чтения. `ci18n_set`, `ci18n_remove`,
`ci18n_clear` и загрузчики отказывают ему с `CI18N_ERR_READ_ONLY`, а не
копируют его в кучу за вашей спиной, потому что эта копия и есть та память,
которую компиляция должна была сберечь. `ci18n_remove_language` работает, а
`ci18n_use_compiled` для языка, который был загружен, заменяет его.

## Когда не стоит

- **Переводчики правят файлы на устройстве, или вы перезагружаете их на
  ходу.** Скомпилированные языки меняются только с новой сборкой.
- **Вы не хотите лишнего шага сборки.** Загрузке текстового файла не нужно
  ничего, кроме заголовка, и это по-прежнему самый простой способ начать.

8-битные платы AVR по-прежнему не поддерживаются. Флеш у них читается
особыми инструкциями, так что скомпилированному каталогу там понадобился бы
свой путь поиска; см. [Встраиваемые системы и размер](embedded-and-size.md#маленькие-устройства).
